# منظومة العالمية — حمودة

نظام تشغيل الشركة (التصنيع، التجاري، اللوجستيك، الحسابات والخزينة) — نسخة حقيقية بخادم خلفي بلغة **Python**.

## ما الذي تغيّر عن ملف HTML القديم

| | النسخة القديمة (ملف HTML واحد) | النسخة الحالية |
|---|---|---|
| تخزين البيانات | داخل متصفح كل جهاز (localStorage) | قاعدة بيانات مركزية على الخادم (SQLite) |
| المشاركة بين الأقسام | لا توجد — كل جهاز بياناته منفصلة | كل المستخدمين يرون نفس البيانات، وتصل التعديلات للآخرين خلال ثوانٍ |
| تسجيل الدخول | حاجز شكلي، كلمات المرور مكتوبة داخل الملف | تحقق على الخادم، كلمات مرور مُجزّأة (PBKDF2)، جلسات بكوكي HttpOnly |
| الصلاحيات | في المتصفح فقط | الخادم يرفض حفظ ما لا يسمح به دور المستخدم (المالية، المخازن، الإعدادات، إنشاء/حذف الطلبيات) |
| تعديل نفس الطلبية من جهازين | آخر حفظ يمسح ما قبله | كشف تعارض: يُرفض التعديل الأقدم ويُحمّل أحدث نسخة مع تنبيه |
| أرقام الطلبيات | قد تتكرر بين الأجهزة | الخادم يضمن رقمًا فريدًا لكل طلبية |
| المرفقات (PDF/صور) | IndexedDB على جهاز واحد | تُرفع للخادم ومتاحة لكل المستخدمين |
| إدارة المستخدمين | تعديل الكود يدويًا | من صفحة الإعدادات: إضافة مستخدم، تغيير الدور، تعطيل، تعيين كلمة مرور |

الواجهة نفسها (التصميم، اللغات الثلاث، مراحل الطلبيات، المالية...) بقيت كما هي.

## هيكل المشروع

```
backend/app/
  main.py         مسارات الـ API (الدخول، المزامنة، المرفقات، المستخدمين، النسخ الاحتياطي)
  db.py           جداول قاعدة البيانات وإنشاؤها
  security.py     تجزئة كلمات المرور ورموز الجلسات
  permissions.py  الأدوار والصلاحيات
  config.py       الإعدادات (متغيرات البيئة)
frontend/
  index.html, app.css, app.js   الواجهة (مستخرجة من ملف HTML الأصلي)
  server.js                     طبقة الاتصال بالخادم والمزامنة
tests/            اختبارات الـ API
run.py            تشغيل الخادم
```

## التشغيل

يحتاج Python 3.10 أو أحدث.

```bash
pip install -r requirements.txt
```

```bash
python run.py
```

ثم افتح `http://localhost:8000` (أو `http://<عنوان-الخادم>:8000` من أي جهاز في الشبكة).

عند أول تشغيل تُنشأ قاعدة البيانات في مجلد `data/` مع الحسابات الافتراضية، وكلها بكلمة المرور `Passw0rd!`:

| الحساب | الدور |
|---|---|
| manufacturing@hamouda.local | قسم التصنيع |
| commercial@hamouda.local | القسم التجاري |
| logistics@hamouda.local | اللوجستيك |
| finance@hamouda.local | الإدارة المالية |
| manager@hamouda.local | الإدارة العليا (حمودة) |

**غيّر كلمات المرور فور أول دخول** (الإعدادات ← حسابي)، أو من حساب المدير (الإعدادات ← المستخدمون والصلاحيات).

### الإعدادات (متغيرات البيئة)

| المتغير | الافتراضي | الوصف |
|---|---|---|
| `HAMOUDA_PORT` | `8000` | منفذ الخادم |
| `HAMOUDA_DATA_DIR` | `./data` | مكان قاعدة البيانات والمرفقات |
| `HAMOUDA_DEMO_AUTOFILL` | `1` | وضع التجربة: قائمة الاختيار السريع في شاشة الدخول تملأ كلمة المرور الافتراضية. **اجعله `0` قبل التشغيل الفعلي** |
| `HAMOUDA_DEFAULT_PASSWORD` | `Passw0rd!` | كلمة مرور الحسابات الافتراضية عند أول تشغيل فقط |
| `HAMOUDA_SESSION_HOURS` | `12` | مدة الجلسة قبل طلب الدخول من جديد |
| `HAMOUDA_COOKIE_SECURE` | `0` | اجعله `1` عند التشغيل خلف HTTPS |

## النسخ الاحتياطي

- من الواجهة: الإعدادات ← «تنزيل نسخة احتياطية كاملة من الخادم» (للمدير).
- على الخادم: انسخ مجلد `data/` كاملًا (`hamouda.db` + `uploads/`).
- استيراد نسخة احتياطية قديمة (بما فيها ملفات النسخة القديمة من المتصفح) من الإعدادات ← «استيراد نسخة احتياطية» بحساب المدير.

### نقل البيانات من ملف HTML القديم

1. افتح الملف القديم في نفس المتصفح الذي كنت تعمل عليه ← الإعدادات ← «تصدير نسخة احتياطية».
2. افتح النظام الجديد بحساب `manager@hamouda.local` ← الإعدادات ← «استيراد نسخة احتياطية» واختر الملف.

ملاحظة: المرفقات القديمة كانت داخل متصفح الجهاز فقط ولا تنتقل مع النسخة الاحتياطية — يجب رفعها من جديد.

## واجهة برمجة التطبيقات (API)

التوثيق التفاعلي متاح على `http://localhost:8000/api/docs`. أهم المسارات:

- `POST /api/auth/login` · `POST /api/auth/logout` · `GET /api/auth/me` · `POST /api/auth/change-password`
- `GET /api/state` — كل البيانات المشتركة
- `GET /api/changes?since=<rev>` — التغييرات منذ مراجعة معينة
- `POST /api/sync` — رفع التعديلات (مع كشف التعارض)
- `POST /api/attachments` · `GET/DELETE /api/attachments/{id}`
- `GET/POST /api/users` · `PATCH /api/users/{id}` — للمدير
- `GET /api/backup` — للمدير

## ملاحظات للتشغيل الفعلي

- شغّل الخادم خلف HTTPS (مثل Nginx أو Caddy) واضبط `HAMOUDA_COOKIE_SECURE=1` و`HAMOUDA_DEMO_AUTOFILL=0`.
- الخادم يتحقق من صلاحيات الأقسام (المالية، المخازن، الإعدادات، إنشاء وحذف الطلبيات)، أما صلاحية كل مرحلة داخل الطلبية (مَن يعدّل أي خانة) فما زالت تُطبَّق في الواجهة فقط كما في النسخة الأصلية.
- SQLite مناسبة لعشرات المستخدمين المتزامنين؛ للتوسع الكبير يمكن نقلها إلى PostgreSQL لاحقًا.
