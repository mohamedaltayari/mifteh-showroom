# تسليم إلى Claude Code: غرفة عمليات المعرض (showroom-os)

اقرأ `../CLAUDE.md` أولًا (قواعد المشروع والخطوط الحمراء)، ثم هذا الملف.

## 1) ما هذا
نموذج أولي (prototype) لمنظومة تشغيل معرض سيارات فارهة في ليبيا. ملف واحد `page.html` (HTML وCSS وJS بلا مكتبات) يعمل كـ Artifact في claude.ai مع قاعدة بيانات مشتركة (`db` capability).
النسخة المنشورة: https://claude.ai/artifact/RnywCbtzqq7RSkAorR1Lfp
صاحب المشروع لا يعمل بالبرمجة، ووقته أقل من 5 ساعات أسبوعيًا. الأولوية لما يعمل وليس لما يبدو معقدًا.

## 2) الأقسام (تبويبات)
لوحة المدير، المعرض (المخزون)، الشحن، المبيعات، المحاسبة، التسويق، الموقع. الدوال: `V.manager` و`V.showroom` و… في آخر الملف، والنماذج: `openCar` و`openSale` و`openLead` و`openTx`.

## 3) نموذج البيانات (collections)
- `cars`: make, model, trim, year, color, km, engine, fuel, gearbox, origin, vin (آخر خانات فقط), status (ordered|shipping|port|customs|available|reserved|sold), etaDate, arrivedAt, buyPrice, shipCost, customsCost, prepCost, askPrice, features (نص), notes, photosDone, reportDone، وللمباعة: soldPrice, soldDate, buyer, seller, payMethod. علامة `sample:true` للأمثلة.
- `leads`: name, phone, source, carId, budget, seller, stage (new|contacted|test|nego|won|lost), nextAction, nextDate, notes, createdAt.
- `tx`: date, type (income|expense), category, amount, carId, note.
- `ideas`: n, title, kind (pitch|content|event|auto), bold (1-3), hours, cost, hook, how[], guard, status (new|chosen|maybe|skip).
- `web`: n, title, why, done.
- `settings/main`: currency, agingDays.
بيانات تجريبية جاهزة في `seed/` (58 مستندًا) وفي `dev-harness/seed_all.json`. أنشأها `dev-harness/seed.py`.

## 4) كيف تجرّبها محليًا بلا نشر
```
cd dev-harness
python3 build_test.py        # يبني test.html
npm i playwright             # مرة واحدة
node shot.js                 # لقطات لكل تبويب على الحاسوب والجوال
```
`stub.js` قاعدة بيانات وهمية في الذاكرة تحاكي واجهة `claude.use("db")`. الخطوط من Google Fonts قد لا تُحمَّل بلا إنترنت، وهذا لا يعتبر خطأ.

## 5) المطلوب منك أولًا: التحقق
1. شغّل الاختبار المحلي وافتح كل تبويب (فاتح وداكن، حاسوب وجوال 390px) وتأكد من غياب أخطاء الـ console.
2. جرّب هذه المسارات بالنقر (Playwright) وتأكد من النتيجة:
   - إضافة سيارة ثم تعديلها ثم حذفها.
   - سيارة في «الشحن»: زر المرحلة التالية حتى تصير «جاهزة للبيع» ويُضبط `arrivedAt`.
   - عميل: نقله بين المراحل، وعند «تم البيع» يفتح نموذج البيع، وبعد الحفظ تصير السيارة `sold` ويُنشأ قيد دخل بالدفعة والعميل `won`.
   - المحاسبة: مستحق على مشترٍ ثم «سجّل دفعة» فينقص المتبقي.
   - «احذف الأمثلة» يحذف السيارات والعملاء والقيود التي عليها `sample:true` فقط.
   - تنبيهات لوحة المدير: سيارة تجاوزت `agingDays`، شحنة تأخرت عن `etaDate`، متابعة عميل متأخرة.
3. راجع النص العربي والاتجاه RTL: الأرقام والتواريخ داخل الجمل، وقص النصوص الطويلة، والجداول على الجوال.
4. تحقق من الوصول (keyboard وfocus وتباين الألوان في الوضعين).
5. أصلح الأخطاء وسجّلها في `CHANGELOG.md` ببنود قصيرة.

## 6) حدود صريحة في النموذج الحالي (لا تفترض غيرها)
- **لا صلاحيات حقيقية.** «الأدوار» مجرد تبويبات. كل من يفتح الصفحة يرى ويعدّل كل شيء. لا سجل تدقيق (audit log) ولا نسخ احتياطي.
- **لا صور للسيارات.** يوجد فقط علامة «صور جاهزة». رفع الصور يتطلب `assets` capability أو تخزينًا خارجيًا.
- **الموقع «معاينة» فقط.** صفحات Artifact بقاعدة بيانات تبقى داخل المنظمة ولا يمكن نشرها للعامة. الموقع العام الحقيقي يحتاج بناءً منفصلًا.
- **العملة رمز فقط** بلا تحويل.
- الحسابات نقدية بسيطة. لا فواتير ولا ضرائب ولا مصاريف مرتبطة بحسابات.
- لم تُجرَّب الصفحة إلا على قاعدة بيانات وهمية، ولم تُختبر مع عدة مستخدمين في الوقت نفسه.

## 7) التطوير المقترح (بالترتيب، ونفّذ كل خطوة بعد موافقة صاحب المشروع)
1. **بنية حقيقية:** Supabase (Postgres وAuth وStorage) لجداول المشروع أعلاه، مع Row Level Security وأدوار: manager، sales، accountant، marketing. البائع لا يرى الأرباح وأسعار الشراء، والمحاسب لا يعدّل العملاء.
2. **واجهة:** Next.js أو مشروع Vite على Vercel، وتُنقل التصاميم والتوكنات والنصوص العربية كما هي (RTL، الوضعان الفاتح والداكن، خطوط Reem Kufi وIBM Plex).
3. **صور:** رفع 15-20 صورة لكل سيارة، ضغطها، وترتيبها. استخدم Storage مع روابط موقّعة.
4. **موقع عام سريع للجوال:** كتالوج بفلاتر (ماركة، سنة، سعر، ناقل، وقود)، صفحة لكل سيارة بمواصفات وصور وزر واتساب برسالة جاهزة وحجز تجربة قيادة بثلاثة حقول، وSEO (عنوان ووصف ورابط ثابت وخريطة موقع). تتزامن مع المخزون تلقائيًا.
5. **أتمتة n8n:** رد واتساب آلي خلال 30 ثانية (يعرّف نفسه بأنه آلي ويعطي رقم إنسان)، تذكير بالمتابعات المتأخرة، ودفعة الأفكار كل أحد صباحًا.
6. **تقارير:** أعمار المخزون وتكلفة الاحتفاظ، الربح لكل سيارة وكل بائع، مصدر العملاء مقابل المبيعات، وتصدير CSV.
7. **حماية وأمان:** لا مفاتيح في الكود، `.env` خارج git، نسخ احتياطي يومي، وسجل تدقيق لتغيير الأسعار والبيع.

## 8) قواعد يجب احترامها
- كل نص واجهة بالعربية الواضحة، واتجاه RTL دائمًا.
- لا مراجعات مزيفة ولا وعود بسعر أو توفر لا يؤكدها المعرض (راجع `../CLAUDE.md`).
- بيانات العملاء (أسماء وهواتف) حساسة: لا تُرسل لخدمة خارجية إلا بموافقة صاحب المشروع.
- أي شيء يُنشر أو يُرسل لعميل يمر بمراجعة صاحب المشروع.

## 9) معايير القبول
- كل مسارات القسم 5 تنجح دون أخطاء console.
- صفحة تعمل بسلاسة على جوال 390px وحاسوب 1280px.
- ملف `CHANGELOG.md` بما أُصلح وما بقي.
- قائمة قصيرة (5 بنود على الأكثر) بأهم القرارات التي تحتاج صاحب المشروع.
